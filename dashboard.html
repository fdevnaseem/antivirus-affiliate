Call tracking — what this proves, and what it does not

Proves: someone tapped a tel: link, on which page, and when.

Does not prove: the call was made, answered, or how long it lasted.

For answered calls and duration, a professional site uses a forwarding number (Google Ads call tracking, CallRail / WhatConverts) or a telephony provider (for example Twilio) that logs the call itself. Try it: open test-call.html, tap the test number, then come back here and refresh — the call tap count goes up by one, and nothing else is claimed.

How to test it yourself

  1. Open index.html in the same browser and same site (for example, the same GitHub Pages URL). Click a Norton deal, a McAfee deal, and finish the 3-question picker.
  2. Come back to this dashboard and press Refresh. Your clicks should appear in Recent events with the right brand, plan and location.
  3. Open test-call.html and tap the test number. Refresh here: Call taps should increase, with no claim that a call was answered.
  4. Open the browser console and type ShieldPickTrack.getEvents() to see the raw event objects the dashboard reads.
  5. To see a full dashboard without clicking 50 times, press “Load demo test data”. Press “Clear demo data only” to remove just that demo data again.

Next steps after this page works: connect the same events to GA4 (same event names, same parameters) for all-visitor data, then build a Looker Studio dashboard from GA4. A backend version would post these same events to a server instead of localStorage.
